# Radios have no Repeat all: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Step 3 of the queue rules: what you play is a list or a radio. A radio has no Repeat all; Repeat all always means "loop the list".

**Architecture:**
- **One rule decides "radio"**, from the play context the players already carry (label and mode, persisted natively in LastSession): mode `radio` (a Home "All", Most saved, Search or Global tap with Autoplay on), or a Jukebox shuffle label.
  - Each player applies it where repeat is set and where a list starts.
  - The phone also applies it where a controller asks for Repeat all.
- **The pure queues lose the single-song exception.** Repeat all on any list drops its suggestions still to come.

**Tech Stack:** Preact + signals (web), Kotlin + Media3 (native), Vitest, JUnit (pure JVM), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-queue-rules-design.md`, version 2: section 2, rule 6, and build step 3.

## Global Constraints

- Change the web and native sides together; the shared spec `tests/spec/queue-rules.json` is run by both `src/player/queueRules.test.ts` and `QueueRulesTest.kt`.
- Each failing test comes first and is shown red.
- `npm run check` passes on every commit, with 0 lint warnings.
- Never show "YouTube Music" in UI text.
- Logs never carry track ids.
- Commit subject `Area: what changed` (Player, Home, Now Playing, Android, Tests, Docs), with a body explaining why, and the session trailers.
- CHANGELOG `[Unreleased]`: one plain, user-facing line per visible change.
- No Android SDK here. Kotlin is checked by the pure harness `scratchpad/ql/run.sh` (QueueOrder + QueueRulesTest) and by CI.

## Review Focus

1. **Repeat all already on, then a radio starts** (a Home "All" tap): repeat becomes off. Repeat song, if on, stays.
2. **The notification's Repeat button on a radio:** it goes Off → Repeat song → Off, never showing Repeat all, not even for a moment in the app's state.
3. **A restart mid-radio** (the screen killed and restored): the context comes back from LastSession, so the button still skips Repeat all.
4. **Autoplay off:** a Home tap plays the feed as a list (`playFrom` already turns `radio` into `list`), so Repeat all is offered. A Jukebox shuffle is a radio whatever the setting.
5. **Leaving a radio for a list** (a genre's Play, an album): Repeat all is offered again, and starting the list doesn't touch repeat.
